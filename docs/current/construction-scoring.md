# 构筑评分与扣分

版本：2026-11-11。规范公式、损失结算和未知边界；不记执行进度。流程见 [S0—S6](construction-workflow.md)，数据字段见 [接口](model-interfaces.md)。

## 3 固定政策与唯一分值单位

评分器版本为 `construction-quality-evaluation-v4-functional-log2`，准入版本为 `construction-before-cb-v3`。旧七项百分制及旧准入版本不再作为现行设计。

| 政策项 | 确定采用的含义 |
| --- | --- |
| 正分函数 | `h(x)=log2(1+x)`；基础权重为 1，保留原始功能分，不压到 100 |
| 同名折算 | Main 首张 1，追加每张 0.9；Extra 首张 1，追加每张 0.8；零张为 0 |
| 普通 Main 用途 | `x=40E/N`，N 为当前候选实际 Main 张数 |
| 具体调用用途 | 经可信关系支持的具体功能使用 `x=E`，不把整张可检索卡的所有功能改为调用型 |
| 主题 | 由原任务、明确功能及主题卡真实配合归纳；默认基础 100%，主要目标额外 +100%、次要目标额外 +50%，同一处理取高档 |
| Side 方向 | 宿主固定方向及权重，总和为 1；采用原设计的先手、后手各 1/2，除非任务已有明确不同设置 |
| 评价范围 | 常驻功能、相关自身条件、显式共同要求、强制影响、泛用用途和 Side 均按本任务适用范围完成 |
| 指定参考 | `pass.mode=reference_ratio`，`minimum_reference_ratio=0.8`；参考与候选使用同一评价器、政策和任务口径 |
| 无指定参考 | `pass.mode=none` 显式表示不适用相对门槛；仍检查政策、完整性及原任务硬条件 |
| 数值精度 | 内部计算与比较不先四舍五入；格式化仅用于展示；不得用显示舍入降低 80% 门槛 |

政策结构继续由 `construction_progress.quality_policy` 校验，评价配置继续由 `construction_quality.quality_config` 校验。新版本移除 `targets/default_target` 饱和评分、七项权重、分区分配、固定卡位罚分和 `structure_accepted` 对旧结构的批准开关。新版本的算法含义由版本及配置确定，不保留“接受旧七项结构才能过关”的遗留条件。

新政策保留 `version`、`source`、`quality`、`pass` 和确有原任务依据的 `metrics`。`quality` 包含 `evaluator_version`、`function_dictionary_version`、`theme_rules`、`side_directions`、`required_scope`。`pass` 在相对模式中保存参考身份、牌表绑定与比例，在无参考模式中不要求虚造一个阈值。参考 Evaluation 保存于同一 construction_progress 的 `reference_evaluation`，作为 gate 的显式输入；不放入政策本身，避免“参考结果绑定政策、政策又包含参考结果”的循环绑定。旧百分制指标路径不能机械搬到 log2 单位；只有单位和含义未变的原任务必要指标可以保留。

政策缺失与显式无参考不同。前者仍返回 `quality_policy_unconfigured`；后者是完整配置中的一种正常模式。2207、2210 读取各自已经指定的参考，2610 自主主题不套另一主题的参考。需要的主题规则尚未实现时报告具体配置缺口，不能以零加成代替；通用无主题任务则显式采用空主题规则集。

锁定社区脚本的普通每回合次数可与同一印刷效果对齐。卡文编号、发动事件、次数上限和共享范围一致时，静态库存关系使用该脚本次数键。Clone 的不同发动窗口沿用同一个印刷效果；不同效果若共享次数，也共同占用同一资源池。缺失、动态或冲突的 Lua 证据保留对应状态，既有卡文与裁定仍提供处理、选择及局面条件。候选与参考使用同一脚本资源及抽取器版本，变更资源代次后重算相应评价。

锁定 Lua 的送墓选择可补充印刷处理中缺失的选择域。发动时检查自方卡组有足量合格卡，结算时选择固定数量并以效果送墓。选择组与该组唯一成员、非空守卫与提前返回、客户端提示和不同局部命名沿同一回调处理。库存沿用主题、卡种、种族和等级谓词。排除规则卡名时，按卡库别名及锁定 core 的第二卡名表转入现有库存谓词。已明确的印刷选择域优先，实际盘面中的可送墓由规则引擎判定。回调证据保留发动检查、结算选择、过滤和移动的脚本跨度。

结算从手卡送墓后从卡组特召时，依据相邻处理块和有序关系绑定前序资源。库存沿用公共选择和整数实体分配，分别核对消耗的费用、送墓的手卡及卡组特召对象。发动卡占在场时也保留其实体。混合来源、可选分支和其他结算仍按其各自的处理证据判定。

## 5 正分和三次修正

### 5.1 投入与分通道聚合

同名组的折算函数为：

```text
E_main(0)=0；E_main(n)=1+0.9(n−1)，n≥1
E_extra(0)=0；E_extra(n)=1+0.8(n−1)，n≥1
普通 Main：x=40E/N
受支持的具体调用用途：x=E
Q_f(X)=log2(1+X_f,base)+Σ_t α_t log2(1+X_f,t)
```

K 始终是整数实体数量。E 是投入价值，不能作为材料、成本、次数或库存容量。同名硬一次的三张 Main 配置仍为 E=2.8；次数约束作用于明确的共同 use。

对每种一致事实补全，在同一计分功能中先合并不重复的有效来源，再分别计算基础和主题通道。单一不可分条件的可用性为 0 或 1；未知保留不同补全，不取 0.5。完整六份代价不能支付时，该模式输入为零，不取 5/6。若存在真正独立可用的三份模式，保留它支持的贡献；若高档模式没有单独获得增量分，就不虚构一笔“失去高档”的罚分。

同名折扣按有效来源集合的数量结算。可互换副本重新排列不改变 E；调用型第三张确认无用途时，从 E(3) 变成 E(2)，不因它在输入列表的位置不同而撤销不同权重。同一同名来源组、同一功能只能有一种经宿主确定的计量模式；不能把同一份投入拆成普通与调用两份。不同真实功能可以有不同模式。

Side 的同名增量按常驻与换入来源的合并数量计算，不能另起首张。资源与支持判断影响有效来源后，重新计算对应组的输入；不要把解析节点的数量当作副本数。

基础和主题分别使用 log2。增加有效非主题来源只增加基础输入，不进入主题分母，也不稀释原有主题投入。若新增 Main 卡改变 N，则全部普通 Main 通道按新 N 重算，这是配置变化本身。

### 5.2 主题与目标自动加权

明确功能目标优先；没有明确功能目标时，从主题卡的真实配合归纳核心机制和直接配套。宿主依据固定任务、完整环境卡池、公开主题事实及效果关系生成规则；候选不能自报权重、主次或加分标签。默认基础权重100%，主要目标额外+100%，次要目标额外+50%，对应公式增量1、0.5。这两个数值是已采用的工程默认值，不记作用户逐数指定。

同一处理同时承担主次作用时取主要档，不按配合条数累加；重复接收方或重复证据不能制造新分。卡名、系列号、频率本身不加分。其他主题不继承珠泪专用规则；显式普通无主题任务使用空规则。旧有明确独立主题规则可兼容，但须同批固定、真实独立且不重复计同一主次作用。

直接配合按卡文和牌表检查区域、所有方、原因、对象、完整代价、素材、次数和适用限制。融合效果只连到素材要求与牌表相容的融合怪兽。效果送墓与作为代价送墓分别核对；检索与被检索卡的堆墓功能分别归属。随机送墓仅提供有机会命中的配合。水仙女人鱼②取自己场上一只怪兽为对象。处理时特殊召唤成功才会把仍有效的原对象送墓，两项处理视为同时。构筑判断此配合时，特殊召唤的怪兽与送墓对象要能由不同实体满足。具体局面和动作次序交给基础 CB。

基础功能成立而主题配套不成立，只撤销相应加权投入；功能本身失效则撤销其基础及相关通道。主要/次要的准备方、接收方及必要对象须满足同一换备情境的真实区域容量。未采用的可选限制不污染全局；已采用的限制撤回受损配合。

### 5.3 同一个 V 计算 P、V1、V2、S

V 对规范化后的输入应用上一节 Q，并按Side 节结算 Side。P、V1、V2、S 使用完全相同的 V、实际牌表、N、同名折扣、主题和方向权重。

| 阶段 | 输入变化 | 解释差值 |
| --- | --- | --- |
| P | 当前真实配置及宿主认可功能在相关配套成立时的潜在输入 | 仅作为解释起点，不包含参考牌表的缺席功能 |
| V1 | 检查对象、区域、事件、完整成本、完整素材及自身条件 | D1=P−V1 |
| V2 | 检查显式共同用途的整数资源、次数、顺序和限制 | D2=V1−V2 |
| S | 施加与已计用途绑定、尚未结算的强制负面影响 | D3=V2−S |

以最终输入直接计算 S；差值仅用于解释 `P−S=D1+D2+D3`。先算 S 再减差值属于重复扣分。原始 E、主题权重和旧百分比都不能直接当作损失金额。

数值结算以“阶段、功能家族、通道、情境”汇总前后输入。相同收益受多个原因影响时合并原因与来源集合再重算；多个原因不能分别从原 P 计算一次罚金。不同真实功能即便因同一个缺件失效，仍分别体现其损失。同一功能有组件外来源时，金额必须连同全部来源计算。

三次修正是事实结算顺序，不是三段行动模拟。若同一损害已经在 V1 或 V2 体现，后续只追加原因，新增金额为零。多个条件共同缺失时，单独修复一项可能恢复零分；反馈应列共同修复组，而不把每个原因的反事实收益相加。

参考算例直接承接附件：三个通道由 (4,3,2) 变成 (3,2,1)，损失约 1.321928；并非基础和两项主题相加扣 3。三张同名 Main 对应三个 2.8 通道，潜在分约 5.777998；仅两项主题失效时保留基础约 1.925999。

## 6 条件 资源与强制影响

### 6.1 自身条件和替代路径

库存检查继续复用 `InventoryDependencies`，保留完整区域/对象谓词、效果来源和未覆盖信息。按2026-11-10用户最新纠正，实体库存用于静态配置、资源转换和配套判断；不要求提供或证明当前已到手、在场、入墓。阶段、触发事件、卡的发动和规则动作描述能力的适用范围。已知适用范围直接进入评分。完整代价、数量、素材、次数、自肃和必要配套仍检查。卡文中的必要对象或代价尚未读懂时，在原效果或选项记录一次缺口。

素材使用完整谓词和不同实体的联合匹配，不能只按类型计数。一次动作的全部代价必须在同一分支里可支付。`all` 保持全部要求；`any` 保持逐分支合法替代。不同分支不能各拿一部分资源拼出不存在的可行方案。

沿用现有有界递归和整数匹配。只问单一用途能否成立时，找到一份已确认的完整分配即可停止。没有确认解时保留会影响评分的未知条件。共同用途和换备容量确实依赖分配时，继续保留所需的备选分配并回溯。先约束较紧的需求，尝试完整分配；每个替代分支持有独立资源状态，失败时恢复。不得把贪心失败当作无解；预算耗尽返回 unknown，不能通过启用另一个外部求解器规避边界。不额外引入 SMT 或第二套规划器。

静态配套关系保留通常召唤、特殊召唤手续、其他效果和替代入口；未找到适配入口不等于没有入口。不能先从具体当前状态搜索路线，再以没有见证为由否定配置能力。真正的循环配套、资源争用和必需功能仍按已声明范围检查，具体起点与操作路线验证属于基础CB。

### 6.2 显式共同用途

联合检查限于一次效果的完整处理及宿主显式声明的 `joint_required`。两张卡的效果能配合时，各自检查其投入、代价和素材。静态共同用途保留明确写入的资源、次数和先后约束。

资源记录至少包含实体/池、区域、数量、consume/presence、占用或保留范围、可重用条件、转移来源与生效范围。次数键区分卡名、效果、单卡及回合/阶段作用域。只在已支持的回收或转移条件下复用实体，不因为名称相同便判定两次消耗，也不因同一张卡换了区域便无条件当作新实体。

共享实体、次数、限制、受损收益相交的用途形成局部组件，统一检查，避免把三对冲突当成三笔罚款。组件只解决原来的 all/any 要求：all 失败撤销依赖共同成立的收益，any 有合法分支则保留。不得临时改成“选最好一项”来满足原本要求共同完成的任务。

两个替代通召入口各自保留配置价值；明确要求同一范围内两次通召时才检查通召容量。A 检索 B 与 C 从卡组送墓 B 作为替代入口可以共用一张 B；若原接续要求先取走 B 再从卡组取 B，则需要第二份、合法返回或其他匹配对象。受损的是具体接续支撑，不是 C 在所有范围中的功能。

### 6.3 强制影响与定价边界

正面收益和必然伴随的处理共用同一个 use。强制影响只有同时满足以下条件才改变 S：来源属于当前候选；该用途在当前情境取得收益或被原任务要求采用；影响作用于同一范围的已计收益；损害尚未结算。

先按候选库存、用途范围和实际问题过滤 `harmful` 等宿主事实，再展开影响。某张未投入卡的负面事实、其他方向的限制、未计入且未被要求采用的可选副作用均不扣当前候选。

发动后限制和整回合限制分开。依据声明的先后约束判断冲突。单项用途遇到有例外的限制时，先按限制筛选对象，再确认有一组完整合法的分配。会改变评分、Side 容量或共同用途的对象选择继续单独核对。卡文或已声明约束有缺口时保留 unknown。强制改变送墓去向、清空资源或消耗另一用途唯一需要的资源，应定位受影响的具体来源与通道；若它同时带来真实独立主题收益，按原规则保留该收益。

LP、手牌等费用先检查可支付性、事件和已计用途争用。没有固定资源效用时，其他独立负担只记 `unpriced_effect`，不发明“弃一张扣一分”一类价格。该标记不阻止已定义功能目标下的完整评价，也不声称已经计入所有资源偏好。

不设置超 40 张、空 Extra、必要伴生、同名 HOPT、未分轴卡位或接近 100 的附加罚款。无功能 Main 卡的浓度影响已进入 N；无害、无独立功能、未挤占已计用途的 Extra 填充可以保持同分。不同收益的真实损失继续累计，不设置掩盖后续缺陷的全局罚分上限。

## 7 Side 的完整情境增量

R 是未换入时的常驻 Main/Extra 有效投入。对每个固定方向 d，X_d 是在该方向的相关换入用途下，重新核对来源、配套、资源和限制后的全部相关有效投入。

```text
Side_d = Σ_f [Q_f(X_f,d) − Q_f(R_f)]
S = Σ_f Q_f(R_f) + Σ_d π_d Side_d
当 Σ_d π_d=1 时，同一组事实下 S = Σ_d π_d Σ_f Q_f(X_f,d)
```

R+Y 只是常驻功能保持不变时的特例。Side 恢复常驻功能时，恢复量进入 X；被计入的换入用途必然损害常驻功能时，损害也进入 X。增量可以为负，不得截成零。解释中的常驻结果 R 保持原义，不能把方向内损害反写成第一局常驻缺陷。

Side 不能支持 R 的必要条件。计算 X 时建立隔离的方向情境，将所选用途的 Side 来源按卡片类型投影到允许的目标区域，并保留 `origin=side`；不要把 Side 资源塞进常驻资源池。静态检查组合依赖、区域类型、同名限制和可换入数量容量，不要求具体换出名单，也不宣称已经生成合法换后牌表。当前任务区域容量为零时，不假装可以在保持该区张数的换备中增加该区卡。

普通 Side Main 用途仍使用当前 N；不把 Main+Side 的张数作为虚拟 N。常驻同名 n 张、相关 Side m 张的新增折算为 `E(n+m)−E(n)`。恢复与失效后统一重算有效来源和各通道，不能在每个方向、每个问题或每条证明里重新领取首张奖励。

方向内的真实替代工具仍按配置用途处理，仅显式共同要求联合检查；不能将互斥模式拼成一项共同收益。一个效果应对多个同义问题不增加基础功能数。方向由宿主固定，候选不能只选自己最有利的方向来平均。

允许空 Side 的任务仍输出“已评价、增量为零”；证据未接通是 unknown 或 deferred，不得伪装为空 Side。任务明确不适用 Side 时记录 not_applicable，所有候选和参考使用相同范围。

## 8 相关未知与结果完整性

设 Ω 为与已知事实、分支互斥、共享资源和用途范围一致的补全集。每个 ω 内完整计算 P(ω)、V1(ω)、V2(ω)、S(ω)；最后分别求各结果的界。不能使用 lower−lower、upper−upper，也不能把独立求出的 D1/D2/D3 极值相加来代替 S 的区间。

相同未知事实共享同一个标识，基础、主题、Side、强制影响和候选/参考比较不能给它互相矛盾的取值。简单独立单调情形可以直接按输入界求值；出现相互影响时，按局部约束组件处理。数值计算仍汇总同一功能的全部来源。

未知条件超过现有精算范围（16 个）时，正式评分与预览都返回保守外界及 `bound_kind=conservative`，并保留未定的事实。精算范围内的计算仍可分片续算。若效果语义尚未识别，连有限潜在功能上界也没有依据，则 upper 为缺失并标明 `unknown_scope`，不用“每张最多若干分”补造界。外界可以用于保守排除，不能据此宣布最优或完整。卡效或规则覆盖已有明确缺口时，保存诊断和保守界，停止为该候选继续枚举未知条件。候选覆盖缺口先交给构筑流程处理，参考比较仍使用相同评分口径。

`unknown` 是本次静态范围内语义未确认或完整资料尚未被正确消费；`deferred` 是应评但本轮没评；`not_applicable` 必须来自任务范围。完整性检查覆盖规定的语义与硬条件，不由分数端点是否相等决定。当前手卡、场上状态、具体堆墓结果、对方当前对象和实际操作序列不属于构筑输入要求，不能因未提供这些状态而阻断计分或完整性。已定义为只记录的 unpriced_effect 也不被重新变成未知币值门槛。

候选与参考相对判断使用同一口径的 `Δ=S_candidate−0.8 S_reference`。能够共享未知事实时联合计算 Δ；没有共享约束信息时，`[L_c−0.8U_r, U_c−0.8L_r]` 是保守外界。下界≥0 表示分数条件已满足，上界<0 表示已确认低于门槛，其余待补信息；任一必要界缺失则相应结论保持未定。分数条件已满足不代替完整静态阶段。
