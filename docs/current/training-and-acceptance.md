# 训练、反馈与验收

版本：2026-11-11。训练计划与实际执行授权分开；本次资料归一不恢复暂停作业。

## 执行设备

后续训练和正式运行使用 GPU。模型与输入必须实际处于显式选定的 CUDA 设备，设备不可用时报错，不静默回退 CPU。CPU 白名单只用于软件回归，不能代替 GPU 验收。规则引擎、静态评分、I/O 等宿主计算仍按其实现执行，使用 GPU 不等于这些步骤已获得 GPU 加速。

训练恢复保持检查点设备、优化器状态和随机状态绑定。旧 CPU 检查点不能只修改元数据便作为 GPU 训练恢复；GPU 推理迁移与训练状态迁移分别验收。环境检查和项目 GPU 小样验证见 [本次 GPU 检查](../reports/2026-11-11-gpu-environment.md)。

CPU→CUDA 训练迁移以已闭合课程边界为单位：先验证源模型、资源、任务、DataIndex 和游标，再搬运实际参数与优化器矩，保留调度器及 CPU/独立采样随机流，使用明确种子建立新的 CUDA 随机流。源边界保留，新边界单独保存并完整恢复；验证后的下一次同设备更新应一致，跨设备数值与随机序列不作逐位一致承诺。正式入口、独立依赖锁及操作见 [CUDA 环境与课程迁移](../development/cuda-runtime.md)。

## 训练路线

先分别建立决斗、目标、优化与统筹基础，再交替协作。决斗以PPO为首版基线，可由引擎验证的bot/搜索轨迹模仿热身；PPO只消费当前策略采样，旧轨迹用于分离的监督/蒸馏或重新采样。目标模型学习搜索及规则验证的目标和路线，预算内未找到不能标为不可能；优化模型学习真实候选比较和修改；统筹从可追踪调度记录学习质量/成本分配。

协作顺序为冻结决斗策略评构筑→更新构筑→训练决斗→冻结新驱动并统一重评。不把驾驶水平上升误当构筑改善。四个角色分别记录样本、实际optimizer.step、参数变化、更新后选择及保存恢复；前向、规则改牌、记录反馈和生成偏好本身不等于发生学习，零更新必须解释。

主训练参考与对手构筑独立登记，不能按文件顺序或文件名猜用途。2207/2210参考只用于独立评价和允许的功能提示，learner使用模型生成并按现行流程通过的候选。指定参考不能填充生成池、恢复成品或提供固定目标。对手允许使用现成构筑，其间接示范应披露。

胜负是决斗主奖励，目标终场、资源利用和抗打断妥协作辅助；不奖励无意义展开长度或怪物数量。对局、搜索、自博弈生成主要轨迹，少量录像用于校对，不把遗失的大规模历史轨迹或视频转录变成前置。完整对局分组拆分训练、验证和独立终验，冻结未参与调参的构筑、驾驶策略和种子。

## 预测与条件反馈

构筑或统筹在冻结观察前登记环境平均胜率预测，绑定候选、决斗驱动、对手、先后手、环境及统计单位。只有实际结果明显低于事先预测时，20局观察门槛触发重评，50局门槛触发重构。仅达到20或50局不构成低表现证据；不是每20/50局无条件优化，也不是每份构筑交付前都先打满50局。

“明显低于”的实现口径必须可追溯，不把曾经的固定10个百分点、额外检查间隔或统计上界当成用户硬要求；不得用附加条件压制已经成立的反馈。误差、统计窗及BO1/BO3单位按采用的版本化政策记录。旧百场/千场规则由20/50修订替代。

记录候选父谱系、有效观察窗口、已消费事件和触发边界，不靠换ID、下调预测或清空计数消除信号。调度处理防饥饿、去重、冻结观察和归因，让反馈真实进入下一轮候选与学习。新发生的触发不能被本轮只消费旧边界的确认清除。

静态参考不足与CB失败分别计数：参考不足只计正常完成且可判定的尝试，第2、3、4次确认不足分别给主轴、副轴、泛用的功能/配套提示；通过后重置连续计数。不暴露参考卡名、配方和精确投入。CB两次正常完成无有效路线回优化；unknown、deferred、配置错误、中断和重复回执不计正常失败。正式对战使用本候选自己的成功基础CB证据。

## 正式能力验收

2207/2210按含换备的BO3大场统计：外战至少60%，对独立强参考珠泪内战接近50%。至少200外战BO3＋200内战BO3，报告95%置信区间、实际先后手和分对手结果；边界或区间过宽时补样本，预算不足如实记证据不足。不能用对称自博弈的总体50%证明强度。内战“接近”的容差与区间通过规则尚未具体冻结，使用时明确，不自定45–55%。

2610第二阶段按实际小局的实际先后手分别统计，先手严格>49%、后手严格>39%，两项同时满足；平局不计胜，不用综合或大场胜率替代。旧200内战＋200外战独立配额如何映射自主主题课程仍是未定项，不能擅自删除旧样本要求或把训练量替代终验量。

构筑验证合法性、原目标、功能与配套、静态比较、CB适用条件、随机依赖、启动/废件/抗打断及独立对局表现。概念用跨局面与构筑比较检验，不能以单套牌胜率代替。泛化至少使用两套未针对训练且机制不同的卡组，对比基模＋LoRA与同结构随机初始化在公平微调预算下的学习速度、操作和构筑改进。曾作对手间接见过要披露。

LoRA用于环境、禁表、新卡组的版本化适配，先更新数据、规则和回归，再按需要微调。检查新任务收益、旧任务退化、时延和资源；加载成功不等于迁移有效。适配器组合、路由或合并不预设无限叠加有效。

## 预算、阶段与资源

约100 GPU小时是总上限，按单卡累计实例小时计算；安装、下载、空转、失败、教师推理和评估均纳入。初始分配为吞吐与小训练5、2207为25、2210为25、2610为20、迁移和正式验收10、故障重训复验15小时，可按实际结果明确修订，不按日历自动晋级。多卡预算换算、算力采购和外部API另有实际授权；停止进程不等于停止计费。

软件阶段交付模型/规则/数据接口、资源导入、训练入口、恢复和自包含交接；训练阶段检查GPU实际使用、吞吐、数值、恢复及正式课程；PC产品阶段才做客户端互操作、界面、量化与端侧验收。已经明确的运行不新增预检批次，运行中维护合法动作、预算和保存，具体错误定点修复。

记录云训练、PC推理和微调的各模型及全链路CPU、RAM、GPU/显存、加载、端到端时延、吞吐、磁盘和可得的温度功耗，绑定硬件、驱动、精度、并发、搜索预算、模型与任务规模。PC决斗报告中位数及P95/P99、超时和投降结果，构筑报告真实完成阶段；性能目标是待验证指标，不能由静态单测推定达标。
