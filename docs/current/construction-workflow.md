# 构筑流程与基础 CB

版本：2026-11-11。以下阶段适用于固定任务、自主主题、CLI 和本地服务。评分细节见 [评分与扣分](construction-scoring.md)。

## 固定的阶段、职责及回退

| 阶段 | 目标行为 | 输出与交接 |
| --- | --- | --- |
| S0 任务固定 | 固定 BuildTask 中的目标、硬性张数、明确存在的路线目标与必需发动、环境卡池、区域上限和环境。用户任务与宿主规则须区分；临时候选名单及每轮检索结果不改变原任务。 | 原任务与约束。卡片目录、全库效果资料可以作为可查询资源准备，不先挑一批具体卡来决定粗逻辑及整个任务的允许范围。 |
| S1 目标模型：第一层骨架 | 先提出无卡ID粗逻辑；狭义主题才按有来源的主题事实筛轴，广义目标跳过该筛轴；随后形成轴骨架候选。 | 骨架及未填卡位交给优化模型。不能先固定具体卡名单，再把名单中的效果反推为模型必须使用的逻辑词表或用户目标。 |
| S2 优化模型：多轮候选 | 在原任务内调整配套、数量、泛用、主卡组／额外卡组／副牌组；按需要继续查询环境卡池和补召回。先提出骨架补全、轴组合、配套修复和换卡方案，按规则及现有模型挑选后，每轮最多生成 5 份完整牌表。 | 本轮候选及其来源、版本、修改和反馈。预算限制本轮工作量，不把首次召回封闭成永久范围。 |
| S3 统一静态评价 | 每个候选使用同一评价器、同一配置，将两层结构及当前统一计分结果装入同一份 Evaluation，包含区间、失分、完整性和版本。指定参考需要评价时也使用同口径，参考问题保留明确状态，不在S2产生成品候选前另建一条独立评价门槛。 | 候选自己的 Evaluation。适用范围内的未知、未完成及预算未覆盖保持真实状态，不填零或伪造完整分。 |
| S4 选择与排序 | 两层结构／比较事实与静态分共同使用同一份 Evaluation，按最终有效分 S 排序，真实同分使用模型顺序及稳定索引；选择、保留、重选、反馈和学习标签不各算一套分。 | 已评候选的顺序、本轮最优构筑和比较理由；需要比较的候选未评完时保留待评队列与游标。 |
| S5 准入 Gate | 检查张数、禁限、必要功能与配套；检查静态完整性；有指定参考时，使用各候选的联合条件比较，按最优构筑的区间结果判断比例条件。高分不能覆盖硬条件失败。 | 未过回S2；连续两次正常完成且可判定的失败才开始分层提示。开发／训练内部片结束自动续算；上线到期停止新增候选，完成当前批次的S3—S5并交付真实状态。真实暂停保存并等待恢复。unknown／deferred、配置错误和重复消费不冒充正常完成失败；静态通过后只保留最优构筑，满足独立授权时仅对它执行 S6。 |
| S6 基础CB | 前置条件为静态通过与显式执行授权。用积木组织路线，再绑定具体卡，核对发动条件、代价、次数与资源，最后由规则引擎搜索见证。沿用已确认的线性主干及随机结果边界。 | 两次正常完成仍无有效路线时回S2；有见证则输出路线及适用条件，供决斗计划参考，不把见证动作写成后续对局必须照做的固定序列。 |

S5的静态失败和S6的CB失败分别记录，不能相互替代；两条回到S2的路径均须保留任务、候选和尝试归属。

“狭义主题”指明确作为必需轴的系列或种族。它不要求纯轴，不会自动新增主卡12张／额外3张，也不把整副卡组限制在主题卡内。固定任务入口只从最低投入大于0的系列／种族硬约束读取筛轴条件；可选条件和其他功能目标不因此转为狭义主题。

## 随后优化的细节如何承接

- 统一计分使用现行的功能log2、P／V1／V2／最终S及同名折算等规则；主要目标额外＋100%、次要目标额外＋50%是当前默认修订。规则依据任务目标和真实配合，不能由预筛卡名单反过来限制目标。
- S4中的“两层比较＋静态分”不自动恢复已经退出的旧层优先排序或旧七项百分制。当前已确认的最终S约束、同分取舍和统一Evaluation继续承接；若具体比较规则再变，应明确修订该细节，阶段顺序不随之改变。
- S5的完整性按已确认的适用范围判断。无关、未采用的可选效果所带未知限制，不得重新变成全局deferred；真正影响本次评价的未知仍使相关评价不完整。
- 候选数量、单片轮数和保存时间片不是开发／训练完成条件。上线运行时限才控制何时停止新增候选并进入评价、选择、Gate及交付；到期不伪造通过。模型结构和候选枚举／模型选择的具体实现另按现有接口核对，不能借这些实现细节颠倒S0—S6。


## 5. 基础 CB 的范围

基础 CB 是在明确起点和已知前提下，预先确定合法动作次序并说明其产出或关键节点的线性路线。起点、目标和动作依照通用效果及规则语义描述，不限定卡片、主题、动作种类或特定数量；可以有多条对应不同起点的路线。终点可以是资源准备、检索、场面或其他明确目标，不以某类召唤方式定义基础 CB。

2026-11-02 用户进一步确认：基础 CB 可以包含固定的随机堆墓动作，只是不推理命中后的分支。通用边界据此按依赖关系划分：一个动作若能由已有前提确定执行，即使包含随机抽取、送墓或除外，也可作为主干步骤；尚未确定的具体结果不作为后续动作的已知前提。后续动作的选择、合法性或资源若依赖该随机结果，就不展开；独立于它的已知动作可以继续。对手动态响应后的转线同样不在此阶段求解。

诱发、融合及其他展开动作本身没有被排除。确定的送墓事件、已知素材或其他已成立条件所支持的后续，仍可属于主干。堆 3、堆 5 仅是例子，不能据此设数量白名单或把一般边界收窄为随机堆墓特例。确定的是动作及其前提，不是把未来随机牌序固定下来。

动作记录保留费用、对象、素材、区域、数量、时点、次数与限制，以及费用支付、效果处理、召唤手续或规则处理等真实来源，不将所有动作硬分成 cost／effect 两类。送墓尤其须保留 cost 与效果的区别：光之援军和爆风偏向是用户给出的来源对照，不能由一种送墓原因冒充另一种触发前提。随机／定向与处理来源是独立维度；既有 `costs`、`operations`、召唤手续及事件原因继续复用。

起手条件与自然抽到该起手的概率分别记录。固定起手不是固定未来牌序，单次原生合法执行也不能证明随机结果无关。未知或未支持的路线保持未确认，不作失败监督或已通关依据。

基础 CB 由目标模型排序路线目标，程序搜索动作并由真实规则引擎验证。通用目标表达覆盖任务实际要求的资源、检索、场面和其他产出，不以当前实现偏重的融合／同调／超量定义全部范围。范围记录、静态契约和真实路线验证分别保存。

## 时间、暂停与局部续算

开发和训练模式没有上线到期条件，内部时间片、候选数量和迭代轮数控制单片开销，片结束后自动消费原进度。上线到期停止新增候选，排空当前批次候选与参考的评价、选择和 Gate 后交付真实状态。显式 slice 模式仅用于已有外层调度器。

用户暂停、异常和待确认事务保存在安全边界；恢复沿原任务、骨架、候选和版本继续。除外层游标外，费用/素材/数量/组合选择、共享资源 DFS、回收/返回身份、状态、随机分支、质量和失分计算均保存真实内部游标；不可用“从头重跑再截断”冒充续算。重复恢复不重复评价消费或失败计数。

参考以自己的完整牌表、事实和可选图独立评价，共享候选的政策与环境，不继承某候选选中的图。只在批次仍待评或待比较时保存候选及计算游标。批次完成后只保存最优牌表及其评价，落选记录保留评分、比较和标识。参考输入与已完成评价按牌表、卡库、禁限、效果字典、政策和适用事实复用。政策/规范化/事实变更只使受影响计算重评，保留有效牌表、任务和累计学习。

构筑为静态配置评价：不要求当前手牌、盘面、具体随机结果、对手当前对象或实际操作序列。自身状态联想用于资源转换和配套，对手对象描述应对范围。完整卡文尚未消费归程序覆盖缺口，不能要求用户重新手填同义事实。基本 CB 目标是无对手动态场面与阻抗条件下的资源收益路线；其实际起点、合法动作和随机依赖仍须验证，不成为静态评分的前置真值。
