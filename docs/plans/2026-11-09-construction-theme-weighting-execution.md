# 主题／目标自动加权修正执行书

## 任务与验收口径

本次修正此前两次“全部完成”的错误结论。W3-2、W4-1、W6-2 中缺失的是默认入口自动归纳并实际采用主题／目标加权，而非读取手工 `theme_rules` 的能力。38 条验收的 A10 及这三个固定项须以本次真实证据重新验收；其他既有完成项不重做。

用户已回答：只指定主题时，根据主题卡的真实配合关系归纳核心机制；百分比适用时保持现行公式，并区分主要目标和次要目标。本次采用基础权重 100%、主要目标额外 +100%、次要目标额外 +50%，对应现行 `Σ α log2(1+x)` 的增量 1 和 0.5。具体百分比是据此选取的实施默认值，不记为用户逐数指定。明确功能目标优先；只有主题时从固定卡池中的实际配合归纳。相同功能同时符合主次目标时取较高档，不因配合条数重复加权。

逐项完成标准：

1. 默认构筑入口无需手写 `theme_rules`，可从任务、主题及卡片效果生成固定规则，并在比较候选前固定。
2. 主要／次要目标及百分比有可核对的来源；不更改现行总分公式、基础份数折扣、Side 比例及参考构筑比较方式。
3. 墓地利用、召唤成功诱发、除外与回收等不同机制使用同一套配合判断；不按珠泪卡名或系列号写评分分支。
4. 候选只改变实际配合是否成立；移除必要接收效果、对象、素材、代价或必要条件后，对应额外加权消失或如实成为 unknown。随机送墓不伪造指定卡已被送墓；存在可配合效果与实际已发动分别判断。
5. 所有权、移动原因、区域、对象筛选、数量、代价、次数、互斥及适用限制沿用现有静态关系和库存检查；搜索不继承被检索卡的后续效果加分。
6. 信息不足时记录具体缺口；明确无主题且无功能目标的任务可采用空规则。候选不能自报主题、百分比或主次顺序。
7. 候选、参考构筑、排序、偏好样本和准入使用同一版本的政策；政策变化通过已有修订入口清除旧分数与旧准入，保留原任务及推进位置。
8. 更新验收对齐表、实施报告及当前状态文档，并附可复核的定向静态测试结果。不以“接口可配置”或手填规则测试代替自动入口证据。

## 当前证据和修改边界
