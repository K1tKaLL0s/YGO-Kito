## 2 目标行为与范围

完整行为是：固定任务与政策 → 目标骨架一次 → 优化候选生成 → 逐候选规范化、库存及关系检查 → 同口径评价 → 选择与保留 → 反馈、偏好样本、静态准入 → 未达标继续优化，预算耗尽保存 → 达标后由现有授权控制是否进入 CB。

本次保留双 Transformer 的网络结构、卡片词表机制和已有机制输入，不新增模型、独立评分服务、平行状态账本或第二套资源求解器。目标模型的骨架不承受完整 Main/Extra/Side 成品评分门槛；成品评价由优化阶段完成。优化仍可调整图与配置，但不能改变原任务目标、时期、卡池、主题政策或必要条件。

本次不设计决斗模型或统筹模型，不扩大 CB 搜索范围，不恢复训练，不重做识别网络。识别提供轴成员、效果、功能、条件、资源及未知事实；构筑拥有收益定价。识别置信度、抽到概率、局面未就绪、环境热度和一场输赢均不能自动转成扣分。

`BuildTask.sizes` 当前规定各区精确张数，校验允许 Main 40–60、Extra/Side 0–15 的任务配置。本方案保留该契约：40、50、60 张以及零额外等通过不同的宿主任务配置覆盖；候选不能把固定 40 张的任务自行改成 60 张。计分始终读取 `len(deck.main)`，不以容量、填充张量长度或固定 40 替代实际 N。若以后要求同一任务自由搜索张数范围，需要明确升级任务契约，不在本次悄悄放宽。

## 3 固定政策与唯一分值单位

评分器版本拟定为 `construction-quality-evaluation-v4-functional-log2`，准入版本拟定为 `construction-before-cb-v3`。这些是待实施的新版本，当前文件中的 v3/v2 尚未改变。

| 政策项 | 确定采用的含义 |
| --- | --- |
| 正分函数 | `h(x)=log2(1+x)`；基础权重为 1，保留原始功能分，不压到 100 |
| 同名折算 | Main 首张 1，追加每张 0.9；Extra 首张 1，追加每张 0.8；零张为 0 |
| 普通 Main 用途 | `x=40E/N`，N 为当前候选实际 Main 张数 |
| 具体调用用途 | 经可信关系支持的具体功能使用 `x=E`，不把整张可检索卡的所有功能改为调用型 |
| 主题 | 宿主固定规则 ID、增量、允许原因和接收条件；珠泪规则沿用墓地相关 +1、堆墓 +1 |
| Side 方向 | 宿主固定方向及权重，总和为 1；采用原设计的先手、后手各 1/2，除非任务已有明确不同设置 |
| 评价范围 | 常驻功能、相关自身条件、显式共同要求、强制影响、泛用用途和 Side 均按本任务适用范围完成 |
| 指定参考 | `pass.mode=reference_ratio`，`minimum_reference_ratio=0.8`；参考与候选使用同一评价器、政策和任务口径 |
| 无指定参考 | `pass.mode=none` 显式表示不适用相对门槛；仍检查政策、完整性及原任务硬条件 |
| 数值精度 | 内部计算与比较不先四舍五入；格式化仅用于展示；不得用显示舍入降低 80% 门槛 |

政策结构继续由 `construction_progress.quality_policy` 校验，评价配置继续由 `construction_quality.quality_config` 校验。新版本移除 `targets/default_target` 饱和评分、七项权重、分区分配、固定卡位罚分和 `structure_accepted` 对旧结构的批准开关。新版本的算法含义由版本及配置确定，不保留“接受旧七项结构才能过关”的遗留条件。

新政策保留 `version`、`source`、`quality`、`pass` 和确有原任务依据的 `metrics`。`quality` 包含 `evaluator_version`、`function_dictionary_version`、`theme_rules`、`side_directions`、`required_scope`。`pass` 在相对模式中保存参考身份、牌表绑定与比例，在无参考模式中不要求虚造一个阈值。参考 Evaluation 保存于同一 construction_progress 的 `reference_evaluation`，作为 gate 的显式输入；不放入政策本身，避免“参考结果绑定政策、政策又包含参考结果”的循环绑定。旧百分制指标路径不能机械搬到 log2 单位；只有单位和含义未变的原任务必要指标可以保留。

政策缺失与显式无参考不同。前者仍返回 `quality_policy_unconfigured`；后者是完整配置中的一种正常模式。2207、2210 读取各自已经指定的参考，2610 自主主题不套另一主题的参考。需要的主题规则尚未实现时报告具体配置缺口，不能以零加成代替；通用无主题任务则显式采用空主题规则集。

## 4 数据契约与来源责任

下列契约在现有模块中实现。优先扩展已有 `CardCopy`、`FunctionEvidence`、`UseRequirement`、`RelationFact`、`ResourcePool` 及质量结果，不另建规则语言或存储系统。新增符号名是实施目标，不声称当前已经存在。

### 4.1 五种身份与收益归并

| 身份 | 含义与归并规则 |
| --- | --- |
| `effect_id` | 卡片规则身份、文本版本、效果作用域和稳定段落位置共同定位真实效果；不能只用可能重复的①②编号 |
| `function_id` | 规范语义：动作、来源与到达区域、自己/对方、成本/效果、随机/定向、结果和对象条件；数量、时点、次数作为结构化属性保存 |
| `score_family_id` | 对同一实际计分功能汇总全部来源的键；同义词、解析步骤、图节点和轴名称不能制造新家族 |
| `use_id` | 该效果以什么模式、在什么用途范围和条件下承担功能；用于表达替代、共同要求及强制影响 |
| `source_id` | 当前牌表的真实来源及必要时的副本身份；同名别名归组沿用已有卡库规则；不是一条报告或证明的 ID |

`benefit_id` 由规范计分功能和真实投入来源确定，基础/主题作为其通道。`scope_id`、`reason_code`、证据数量和图节点编号不进入创建另一份同源收益的键。一个来源在同一功能通道中只贡献一次；多条合法替代支撑以“或”支持这份贡献，只有所有替代都失败才撤销。

检索、确认对象、把对象加入手牌若属于同一次检索处理，只计一个检索功能；真实不同的堆墓和融合分别计分。随机堆墓、定向送墓、成本弃牌、因效果送墓触发不能被归并成同一语义。所谓组合增量只有存在已定价的真实功能时才建立收益身份，不能因增加一条关系便奖励联动分。

同一物理来源属于多个轴时，各轴可以展示参与关系，全局只归并一次。通常怪兽、必要搭档、指定素材和代价库存通过支撑关系起作用；有独立战斗或其他功能时才为该功能另建记录。

### 4.2 规范用途记录

`construction_layer_flow.normalize_function_uses` 从当前候选完整 Main/Extra/Side 和 `MechanismCatalog.effect_records` 生成以下逻辑结构，并结合宿主任务与识别提供的事实补齐。图负责用途组织与解释，不决定候选有哪些真实效果；轴外卡也要进入效果覆盖检查。

| 字段组 | 必需内容 |
| --- | --- |
| 身份与来源 | 上述五种身份、`benefit_id`、来源区域、副本或数量、原始效果引用、`evidence_refs` |
| 计量 | `valuation_mode=main_density/called`、同名组、受支持副本数量或副本状态；模式由可信适配器确定 |
| 用途范围 | `scope_id`、常驻或 Side 方向、`requirement_mode=configuration/all/any`、替代分支与依赖组 |
| 硬要求 | `requirement_ids`、`requirement_origin`、`required`、`requirement_status`；原任务或规则来源与组合方式分开 |
| 条件与资源 | 对象/素材谓词、区域/表里/事件/时点、完整代价、整数需求、效果次数键、限制作用范围、合法转移或回收事实 |
| 主题 | 待判定规则 ID、每个通道的语义命中与配套状态；不能直接信任模型给出的“主题卡”标签 |
| 必然影响 | 与正面用途绑定的 `mandatory_impacts`，受损收益/来源/通道及作用范围 |
| 事实状态 | `supported/failed/unknown`；与是否已处理的 `evaluated/deferred/not_applicable` 分开 |

`required` 不能因为一条效果自身存在 all 条件而自动为真。原任务必须共同取得的收益才进入硬要求；可选效果的 all 条件失败意味着该效果不能取得相应分数。外部对手目标与响应条件按固定用途情境解释，不要求从己方库存中找到。

`coverage` 单独记录每张卡、每个相关效果是否已读、是否完成规范化及缺口。已审阅且没有独立计分功能的空集合是合法结果；资产缺失、解析未覆盖和预算未读不能输出同样的空集合。粗功能标签已覆盖不代表具体条件、对象和完整素材已解析。

### 4.3 输入事实与输出损失分开

关系模块输出的是事实变化，不是金额。建议使用现有质量模块中的 `UseImpact` 结构表达 `affected_benefit_ids/source_ids/channel_ids`、`scope_id`、`stage`、`reason_codes`、`evidence_refs`、状态及受影响的有效投入。完整费用失败、共享资源和强制影响都先映射到具体用途，再由计分器重算金额。

旧 `QualityLoss.share` 是旧收益预算单位，不能直接当作对数分或新投入比例沿用。旧 `SlotUse(zone,card_id)` 不能表达同名副本差异，迁移为来源/用途支撑事实，不再产生 `slot_budget` 罚分。旧宿主只有无法无损转换的标量 loss 时返回 `legacy_loss_requires_semantic_rebind`，保留原记录供定位，不静默忽略，也不把该错误生成构筑负样本。

输入仍可使用 `quality_evidence` 这一现有宿主挂接点。基础事实由 ConstructionLayerAdapter 从真实牌表、现有资产和关系层默认生成，不要求外部调用者手填每张卡。宿主 hook 可补充版本化的、绑定候选的 `uses`、`impacts`、`coverage`、Side 情境和 unknown 约束；与已有事实冲突时显式报告，不能覆盖原任务或吞掉不利事实。历史 `generic_fits`、`duplicate_purposes`、`slot_uses`、`losses` 由适配层转换并校验。不能只把两个旧参数补传进旧百分制算法就宣布完成。

每个诊断引用统一生成的损失记录：`loss_id`、受损对象、通道、阶段、原因集合、前后投入、差值或区间、`accounted_by`、共同修复条件和修复后的可恢复分。浓度变化、同名折算等写为 `already_accounted_note`。`unpriced_effect` 记录尚无独立价格的资源负担，不写成“已确认零成本”。

### 4.4 唯一 Evaluation

`evaluate_quality` 保留为纯评价入口，读取同一候选的层结果、规范用途和固定政策，返回以下内容：

| 输出 | 内容 |
| --- | --- |
| 绑定 | 评价器/规范化版本、task、deck、logic、policy、资产/事实版本、评价范围；复用现有摘要机制 |
| 总分 | `score.unit=functional_log2`，`score.value/lower/upper`；value 只在数值已确定时提供 |
| 完整性 | `scope_complete`、相关未知、deferred、系统错误、保守界说明；不靠上下界相等推断完整 |
| 条件 | 原任务硬要求的 satisfied/failed/unknown 与来源；普通可选缺口另列 |
| 解释 | P/V1/V2/S、各功能基础及主题投入、各方向 R/X/增量、统一损失记录、未定价负担 |
| 消费索引 | 各卡/轴/泛用/组合到同一功能记录的引用，以及实际候选版本 |

一份候选记录保存 `deck`、`layer_evaluation`、`quality_evaluation`、评价状态及绑定。candidate trace、learning_candidates、portfolio、当前 candidate、retained_candidates 都必须保留自己的结果。`total.value/min/max` 若因兼容保留，只能是新 `score` 的同值投影并显式带单位，不能维护第二套计算。

绑定分为共同口径与候选输入两部分：共同口径包含 task、policy、评价器、规范字典、资产和事实契约版本、评价范围；候选输入包含 deck、logic 和实际使用的事实内容。比较双方时要求共同口径一致，不要求不同牌表具有相同事实内容。`evaluation_id` 复用现有 digest 对绑定与规范结果生成，供保存和消费引用；无需另造文件校验台账。参考与候选各自绑定自己的输入，不能互换结果。

### 4.5 接口与宿主装配

以下为待实施接口定义，不是本轮新增程序：

```text
evaluate_quality(layer_evaluation, *, policy, facts) -> QualityEvaluation
compare_quality(before, after) -> QualityComparison
ConstructionLayerAdapter.evaluate(..., *, policy, quality_evidence=None)
    -> (selection_order, candidate_evaluations, trace)
construction_gate(..., quality=None, reference_quality=None) -> Gate
```

`candidate_evaluations[index]` 包含 `layer_evaluation`、`quality_evaluation`、`evaluation_status`；原来直接取两层结果的调用点统一改为读取该字段。`trace` 保存比较结果、已评/待评索引及预算原因，不再承载另一套总分。`quality_evidence(task, deck, layers)` 的签名保留，返回上一节定义的事实补充，统一适配后成为 `facts`。

宿主仍由 `source_binding.construction_quality_policy` 提供固定政策；增加 `construction_quality_reference` 承载指定参考的 ID、实际 deck、来源及环境绑定。它只在 reference_ratio 模式必需，与政策中的参考描述一致。由层适配器沿同一路径评价参考并存入当前构筑进度，再传给 gate。无参考模式显式不装配参考，不扫描候选池挑选替代标尺。

单个候选的事实范围来自自己的库存和共同宿主用途契约；同批其他候选的卡只能帮助复用只读资产索引，不能给它提供对象、材料、主题接收方或新增硬目标。改变批次组成不能改变同一候选的完整评价。

## 5 正分和三次修正

### 5.1 投入与分通道聚合

同名组的折算函数为：

```text
E_main(0)=0；E_main(n)=1+0.9(n−1)，n≥1
E_extra(0)=0；E_extra(n)=1+0.8(n−1)，n≥1
普通 Main：x=40E/N
受支持的具体调用用途：x=E
Q_f(X)=log2(1+X_f,base)+Σ_t α_t log2(1+X_f,t)
```

K 始终是整数实体数量。E 是投入价值，不能作为材料、成本、次数或库存容量。同名硬一次的三张 Main 配置仍为 E=2.8；次数约束作用于明确的共同 use。

对每种一致事实补全，在同一计分功能中先合并不重复的有效来源，再分别计算基础和主题通道。单一不可分条件的可用性为 0 或 1；未知保留不同补全，不取 0.5。完整六份代价不能支付时，该模式输入为零，不取 5/6。若存在真正独立可用的三份模式，保留它支持的贡献；若高档模式没有单独获得增量分，就不虚构一笔“失去高档”的罚分。

同名折扣按有效来源集合的数量结算。可互换副本重新排列不改变 E；调用型第三张确认无用途时，从 E(3) 变成 E(2)，不因它在输入列表的位置不同而撤销不同权重。同一同名来源组、同一功能只能有一种经宿主确定的计量模式；不能把同一份投入拆成普通与调用两份。不同真实功能可以有不同模式。

Side 的同名增量按常驻与换入来源的合并数量计算，不能另起首张。资源与支持判断影响有效来源后，重新计算对应组的输入；不要把解析节点的数量当作副本数。

基础和主题分别使用 log2。增加有效非主题来源只增加基础输入，不进入主题分母，也不稀释原有主题投入。若新增 Main 卡改变 N，则全部普通 Main 通道按新 N 重算，这是配置变化本身。

### 5.2 主题判断

墓地相关要求对当前构筑的真实墓地用途有作用和静态配套。堆墓要求操作本身为“自己的卡组到自己的墓地”，并且送墓原因和接收方条件匹配。珠泪政策的 `allowed_mill_causes` 为效果；随机和定向可以分别符合，语义身份仍不同。

有效的主题堆墓可同时取得墓地相关与堆墓两个主题通道。重复登记同一规则只计一次。检索不继承被检索对象的堆墓标签，灰流丽式无效条件中提及送墓不成为自身堆墓，成本送墓也不伪装为效果送墓。

基础功能成立、主题配套失效时只撤销主题输入；功能本身依赖缺失对象时，撤销其基础与相关主题输入。独立效果和其他合法支撑保持原判断。

### 5.3 同一个 V 计算 P、V1、V2、S

V 对规范化后的输入应用上一节 Q，并按第 7 节结算 Side。P、V1、V2、S 使用完全相同的 V、实际牌表、N、同名折扣、主题和方向权重。

| 阶段 | 输入变化 | 解释差值 |
| --- | --- | --- |
| P | 当前真实配置及宿主认可功能在相关配套成立时的潜在输入 | 仅作为解释起点，不包含参考牌表的缺席功能 |
| V1 | 检查对象、区域、事件、完整成本、完整素材及自身条件 | D1=P−V1 |
| V2 | 检查显式共同用途的整数资源、次数、顺序和限制 | D2=V1−V2 |
| S | 施加与已计用途绑定、尚未结算的强制负面影响 | D3=V2−S |

以最终输入直接计算 S；差值仅用于解释 `P−S=D1+D2+D3`。先算 S 再减差值属于重复扣分。原始 E、主题权重和旧百分比都不能直接当作损失金额。

数值结算以“阶段、功能家族、通道、情境”汇总前后输入。相同收益受多个原因影响时合并原因与来源集合再重算；多个原因不能分别从原 P 计算一次罚金。不同真实功能即便因同一个缺件失效，仍分别体现其损失。同一功能有组件外来源时，金额必须连同全部来源计算。

三次修正是事实结算顺序，不是三段行动模拟。若同一损害已经在 V1 或 V2 体现，后续只追加原因，新增金额为零。多个条件共同缺失时，单独修复一项可能恢复零分；反馈应列共同修复组，而不把每个原因的反事实收益相加。

参考算例直接承接附件：三个通道由 (4,3,2) 变成 (3,2,1)，损失约 1.321928；并非基础和两项主题相加扣 3。三张同名 Main 对应三个 2.8 通道，潜在分约 5.777998；仅两项主题失效时保留基础约 1.925999。

## 6 条件 资源与强制影响

### 6.1 自身条件和替代路径

库存检查继续复用 `InventoryDependencies`，保留完整区域/对象谓词、效果来源和未覆盖信息。按2026-11-10用户最新纠正，实体库存用于静态配置、资源转换和配套判断；不要求提供或证明当前已到手、在场、入墓。阶段、触发事件、卡的发动和规则动作描述能力的适用范围，不是本轮必须见证的实际事件。完整代价、数量、素材、次数、自肃和必要配套仍检查，未解析或未接通的完整卡文归程序覆盖缺口。

素材使用完整谓词和不同实体的联合匹配，不能只按类型计数。一次动作的全部代价必须在同一分支里可支付。`all` 保持全部要求；`any` 保持逐分支合法替代。不同分支不能各拿一部分资源拼出不存在的可行方案。

沿用现有有界递归和整数匹配，必要时保留不同分支的资源使用结果并回溯。先约束较紧的需求，尝试完整分配；每个替代分支持有独立资源状态，失败时恢复。不得把贪心失败当作无解；预算耗尽返回 unknown，不能通过启用另一个外部求解器规避边界。本轮不引入 SMT 或新的规划器。

静态配套关系保留通常召唤、特殊召唤手续、其他效果和替代入口；未找到适配入口不等于没有入口。不能先从具体当前状态搜索路线，再以没有见证为由否定配置能力。真正的循环配套、资源争用和必需功能仍按已声明范围检查，具体起点与操作路线验证属于基础CB。

### 6.2 显式共同用途

联合检查只作用于已声明 `joint_required`、一次完整处理或有明确前后的共同接续。不要把整副牌的所有可选效果当作必须同回合全部执行。

资源记录至少包含实体/池、区域、数量、consume/presence、占用或保留范围、可重用条件、转移来源与生效范围。次数键区分卡名、效果、单卡及回合/阶段作用域。只在已支持的回收或转移条件下复用实体，不因为名称相同便判定两次消耗，也不因同一张卡换了区域便无条件当作新实体。

共享实体、次数、限制、受损收益相交的用途形成局部组件，统一检查，避免把三对冲突当成三笔罚款。组件只解决原来的 all/any 要求：all 失败撤销依赖共同成立的收益，any 有合法分支则保留。不得临时改成“选最好一项”来满足原本要求共同完成的任务。

两个替代通召入口各自保留配置价值；明确要求同一范围内两次通召时才检查通召容量。A 检索 B 与 C 从卡组送墓 B 作为替代入口可以共用一张 B；若原接续要求先取走 B 再从卡组取 B，则需要第二份、合法返回或其他匹配对象。受损的是具体接续支撑，不是 C 在所有范围中的功能。

### 6.3 强制影响与定价边界

正面收益和必然伴随的处理共用同一个 use。强制影响只有同时满足以下条件才改变 S：来源属于当前候选；该用途在当前情境取得收益或被原任务要求采用；影响作用于同一范围的已计收益；损害尚未结算。

先按候选库存、用途范围和实际问题过滤 `harmful` 等宿主事实，再展开影响。某张未投入卡的负面事实、其他方向的限制、未计入且未被要求采用的可选副作用均不扣当前候选。

发动后限制和整回合限制分开。已有合法先后关系能够避开冲突时保留收益，顺序未知时保留 unknown。强制改变送墓去向、清空资源或消耗另一用途唯一需要的资源，应定位受影响的具体来源与通道；若它同时带来真实独立主题收益，按原规则保留该收益。

LP、手牌等费用先检查可支付性、事件和已计用途争用。没有固定资源效用时，其他独立负担只记 `unpriced_effect`，不发明“弃一张扣一分”一类价格。该标记不阻止已定义功能目标下的完整评价，也不声称已经计入所有资源偏好。

不设置超 40 张、空 Extra、必要伴生、同名 HOPT、未分轴卡位或接近 100 的附加罚款。无功能 Main 卡的浓度影响已进入 N；无害、无独立功能、未挤占已计用途的 Extra 填充可以保持同分。不同收益的真实损失继续累计，不设置掩盖后续缺陷的全局罚分上限。

## 7 Side 的完整情境增量

R 是未换入时的常驻 Main/Extra 有效投入。对每个固定方向 d，X_d 是在该方向的相关换入用途下，重新核对来源、配套、资源和限制后的全部相关有效投入。

```text
Side_d = Σ_f [Q_f(X_f,d) − Q_f(R_f)]
S = Σ_f Q_f(R_f) + Σ_d π_d Side_d
当 Σ_d π_d=1 时，同一组事实下 S = Σ_d π_d Σ_f Q_f(X_f,d)
```

R+Y 只是常驻功能保持不变时的特例。Side 恢复常驻功能时，恢复量进入 X；被计入的换入用途必然损害常驻功能时，损害也进入 X。增量可以为负，不得截成零。解释中的常驻结果 R 保持原义，不能把方向内损害反写成第一局常驻缺陷。

Side 不能支持 R 的必要条件。计算 X 时建立隔离的方向情境，将所选用途的 Side 来源按卡片类型投影到允许的目标区域，并保留 `origin=side`；不要把 Side 资源塞进常驻资源池。静态检查组合依赖、区域类型、同名限制和可换入数量容量，不要求具体换出名单，也不宣称已经生成合法换后牌表。当前任务区域容量为零时，不假装可以在保持该区张数的换备中增加该区卡。

普通 Side Main 用途仍使用当前 N；不把 Main+Side 的张数作为虚拟 N。常驻同名 n 张、相关 Side m 张的新增折算为 `E(n+m)−E(n)`。恢复与失效后统一重算有效来源和各通道，不能在每个方向、每个问题或每条证明里重新领取首张奖励。

方向内的真实替代工具仍按配置用途处理，仅显式共同要求联合检查；不能将互斥模式拼成一项共同收益。一个效果应对多个同义问题不增加基础功能数。方向由宿主固定，候选不能只选自己最有利的方向来平均。

允许空 Side 的任务仍输出“已评价、增量为零”；证据未接通是 unknown 或 deferred，不得伪装为空 Side。任务明确不适用 Side 时记录 not_applicable，所有候选和参考使用相同范围。

## 8 相关未知与结果完整性

设 Ω 为与已知事实、分支互斥、共享资源和用途范围一致的补全集。每个 ω 内完整计算 P(ω)、V1(ω)、V2(ω)、S(ω)；最后分别求各结果的界。不能使用 lower−lower、upper−upper，也不能把独立求出的 D1/D2/D3 极值相加来代替 S 的区间。

相同未知事实共享同一个标识，基础、主题、Side、强制影响和候选/参考比较不能给它互相矛盾的取值。简单独立单调情形可以直接按输入界求值；出现相互影响时，按局部约束组件处理。数值计算仍汇总同一功能的全部来源。

在现有预算内无法求紧界时返回保守外界及 `bound_kind=conservative`，保留未完成的事实或搜索原因。若效果语义尚未识别，连有限潜在功能上界也没有依据，则 upper 为缺失并标明 `unknown_scope`，不用“每张最多若干分”补造界。外界可以用于保守排除，不能据此宣布最优或完整。

`unknown` 是本次静态范围内语义未确认或完整资料尚未被正确消费；`deferred` 是应评但本轮没评；`not_applicable` 必须来自任务范围。完整性检查覆盖规定的语义与硬条件，不由分数端点是否相等决定。当前手卡、场上状态、具体堆墓结果、对方当前对象和实际操作序列不属于构筑输入要求，不能因未提供这些状态而阻断计分或完整性。已定义为只记录的 unpriced_effect 也不被重新变成未知币值门槛。

候选与参考相对判断使用同一口径的 `Δ=S_candidate−0.8 S_reference`。能够共享未知事实时联合计算 Δ；没有共享约束信息时，`[L_c−0.8U_r, U_c−0.8L_r]` 是保守外界。下界≥0 表示分数条件已满足，上界<0 表示已确认低于门槛，其余待补信息；任一必要界缺失则相应结论保持未定。分数条件已满足不代替完整静态阶段。

## 9 候选 反馈与学习的接线

### 9.1 评价必须先于质量选择

保留 `portfolio` 的有界候选生成、合法池过滤和依赖修复提案。生成预算只定义本轮提出了哪些候选，不是质量判断。模型分可以安排待评顺序和预算，不再替代最终有效分。

`ConstructionLayerAdapter.evaluate` 改为：对已入本轮候选集合的每个候选完成绑定及层事实，组装规范用途，调用统一质量入口，然后调用统一比较器。旧 `compare_layer_candidates` 的缺口和优劣原因继续可用于诊断及修复建议，但不再产生最终质量优先边。

候选进入以下不同状态，不能互相偷换：

| 状态 | 用途 |
| --- | --- |
| 已完成、硬条件成立 | 进入按 S 的质量排序；可生成质量偏好样本；再由相对门槛决定准入 |
| 已完成、原任务硬条件失败 | 保留具体失败与修复方向；不成为准入候选，不伪装为一般低分样本 |
| 相关事实 unknown | 保留区间与决定性缺口，可安排局部核对；不填中点 |
| deferred / 预算未覆盖 | 保留候选、待评索引和原因；不填零、不算连续失败 |
| 配置/解析接口错误或绑定错误 | 返回可定位错误；不生成构筑负样本；已知语义资料不足仍用 unknown |

全部已生成且进入本轮比较的候选必须在最终排序和保留裁剪前取得自己的评价。预算耗尽时保存 `pending_candidates` 和评价游标；可以记录当前已评最优作为 working candidate，但结果标为选择尚未完成。只有剩余候选均已评价，或有可靠上界证明不会影响所需的前若干名，才能提交本轮最终保留集。这里不要求枚举所有可能牌表。

完整且硬条件成立的候选按 S 降序，真实同分才使用现有模型顺序和稳定候选索引。原有策略多样性可以用于生成和同分取舍，不能让更低 S 覆盖已确定的更高 S。各保留候选带自己的 Evaluation；三份保留上限不等于只评前三份。

`fill_with_existing` 返回 `quality_evaluation`、`quality_comparisons`、完整 `learning_candidates`、待评候选和选择状态。`construction_cycle` 直接使用该结果，不再在选中后另算 quality。包括学习后重选在内的所有静态构筑选择使用同一比较器。后续已获授权的真实对战部署比较保留原职责，其结果不得反写静态 S。

### 9.2 统一比较和反馈

`compare_quality(before,after)` 先校验双方任务、政策、评价器、范围、资产及事实口径一致，再比较最终 S。毛值 P、缺件数量、损失比例和模型 logits 不得决定新质量偏好。

比较结果包含双方评价身份、最终差值/区间、`preferred/equivalent/unresolved/incomparable`、硬条件状态和变化的功能引用。事实不足时，可提供有依据的区间优势用于核对优先级，但本次质量学习样本只取完整、硬条件成立的双方。系统错误不比较。

反馈显示 S、适用时的参考比例、本轮真实变化的功能通道、导致变化的来源与条件，以及可修复条件组。归因直接来自 Evaluation；另一个解释模型不能自造分值。各卡与轴的分摊只作展示，按有效输入比例分摊时各份额应回到该通道总分，不能再次累计为全局分。

### 9.3 学习标签与模型边界

`construction_learning.SOURCE` 迁移为 `construction_quality_preference_v2`。`comparisons/candidate_pairs/cycle_pairs/validate_pair` 读取新质量比较，继续使用已有成对偏好训练接口的 1/0 标签；1/0 只表示明确顺序，不表示胜率或 CB 成功。

每对样本绑定 task、双方 deck、双方 Evaluation、政策/评价器/事实版本和实际优化轮次。来自被裁掉但已经完整评价的候选也可进入样本，不能只留下幸存者。沿用每轮限额、跨轮公平取样和去重；同一评价重复恢复或消费不重复增加更新。存在反向冲突的旧记录先检查版本和绑定，不投票决定真值。

`rank_candidates` 学习后重选仍以有效分的已确认顺序为约束；模型分只处理真实同分。`semantic_training.validate` 和现有监督投影接纳新 source 并验证评价绑定，不能继续接受一条旧 `layer_comparisons` 作为新质量标签。历史旧标签保留原版本，不混入新版课程样本。

本次不把最终 S 当作 BuildRanker 的预测输入，也不扩大网络规模。现有卡片与机制特征保持；新评价提供监督和修复反馈。若实施时确实改变已有机制向量的含义，必须走现有 feature/version 兼容检查，不能宣称权重布局相同便自动兼容。

真实参数更新、更新后的决策和 checkpoint 恢复闭环需在将来训练获准后验证；不能把样本契约接通写成模型已经学会。当前方案不启动该步骤。

## 10 准入 记录与恢复

### 10.1 准入条件

完整静态准入依次检查：当前牌表原有合法性；原任务明确必要能力及配套；要求的静态评价完整；新 Evaluation 的完整绑定；适用时的 80% 参考比例。高 S 不能抵消必要条件，普通可选功能失败也不能被升级为新的硬门槛。

`InventoryDependencies` 仍读取全候选库存。`known_deficits` 保留为所有相关缺口的诊断，gate 改为读取带 `requirement_origin` 的必要缺口，而不是看到任意缺件就拒绝。未获得潜在分的必需能力缺失仍会拒绝准入，其数值损失可以为零。

参考必须是事先指定且合法有效的牌表，使用同一政策和评价器重新评价。新政策不接受裸 `reference.score` 替代 Evaluation，不把参考重新标成 70。参考为零分、非法、缺失或不完整时给出具体参考状态；不除以零、不任选当前低分候选充当参考、不自动降级到无参考模式。

`construction_gate`、`CourseAdmissionPolicy.record_completed_construction` 和保留候选重选读取同一 Evaluation。记录入口缺该候选结果时标为待评价，不读取别的候选分，也不回退到旧七项评分。

相对门槛失败计数只累计已正常完成、确认低于比例门槛的构筑尝试。复读、重试、预算耗尽、unknown、配置或资产错误不增加次数。沿用现有 cycle/attempt 归属，连续两次确认不足后的主轴→副轴→泛用提示给功能和配套建议，不泄露参考的卡名配方或精确投入。CB 失败计数另行保留，不转为静态扣分。

### 10.2 恢复与政策变更

扩展现有 continuation 为 schema 3，保存当前候选、每个 retained/pending 候选的评价状态、评价游标、参考结果、原目标骨架、交接链及优化游标。只在候选评价原子步骤完成后提交结果；暂停时保存尚未评价项，不发布半份完整分。

恢复先核对任务、牌表和交接链，再核对评价器、政策、功能字典、资产/事实、图及范围绑定。只有绑定一致的质量记录可复用。旧 v3 百分分、旧 gate 或事实版本变化导致的分数标为 stale，保留牌表和优化进度，作废旧通过状态，安排候选与参考同口径重评。
