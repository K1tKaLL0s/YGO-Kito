## 观察、事件与兼容

`DecisionRequest.prompt` 提供消息类型、界限和可完成/取消状态，`LegalAction.details` 提供效果描述、操作或落点。未知嵌套字段拒绝。旧 DTO 的空扩展字段不序列化，以保持九条冻结轨迹。

扩展观察提供公开位置和面朝上怪兽的实际攻守；隐藏卡不含身份、攻守或未验证的原所有者。可见卡从核心查询真实 owner，controller 独立表示，控制权变化不伪装成原所有者变化。己方手牌按当前控制者验证可见性。策略 seed 仍为 null，牌组查询仍禁止。

v2的`CardView.attached_to/material_count`约束宿主、控制者、可见性与素材数量一致。素材原所有者由已合法查询的owner和真实MOVE迁移；未经过验证的情况明确null，绝不猜为宿主控制者。核心超量素材可先附到额外区宿主，再随宿主移动到怪兽区；素材拔除后后续子序号迁移。`SumSelection`只含可见卡引用与核心提供的数值，不含响应字节/索引；模型特征版本提升，不静默加载旧特征检查点。

除原有回合/移动/战斗/LP/连锁外，本批读取翻转召唤64/65、表示变化53及指示物101/102。特殊召唤的隐藏表示不公开其真实 ID。公共历史只投影明确公开事件；原生提示、候选数、全局事件下标、初始牌序和审计种子均不进入策略 DTO。扩展公开历史仅用于新范围，旧轨迹使用原有投影。

固定`common.h`中54是盖放`MSG_SET`（8字节负载），55才是`MSG_SWAP`，后者仍不支持、明确失败；不把55的16字节格式误用到54。v2手牌洗切33会丢弃过期的手牌序号→owner缓存，随后只从合法可见查询重建；未知归属保留unknown，不用旧序号猜测。

## 验收与运行

```bash
.venv/bin/python -m ygo_kito native-effect-duel --profile configs/effect-duel-v1.json --seed 1724 --option-preference last --trace outputs/effect.json
.venv/bin/python -m ygo_kito native-effect-duel-replay outputs/effect.json
```

`configs/effect-duel-v1.json` 是工程用两套40张主卡示例，不是用户将提供的3＋8套构筑，不代表任何历史环境推荐牌表。接口检查40–60张、数据库OCG身份、主卡类型及别名合并后的社区禁限张数。官方禁表/发行日期/素材许可仍待补齐。

真实正向证据见 [M2f 报告](../reports/2026-10-23-general-protocol-m2f.md)。新整局是可见 DTO＋静态公开卡库驱动的规则基线，不代表模型能力。未知协议、动作/重放不匹配、预算耗尽明确失败；独立进程看门狗、一般卡池、标准客户端回放及 PC 实机仍未完成，阶段1A/1B不据此通过。

额外/素材的新真实证据与可重复完整命令见[本批报告](../reports/2026-10-23-extra-material-feedback.md)和[运行说明](extra-material-feedback.md)。其中同调/超量整局使用明示路线意图后转可见规则基线，非训练模型；真实规则对局与合成协议负测分开记录。
