本增量沿[统一设计](../plans/2026-10-22-unified-development-spec.md)，承接[v4私有选择/分层策略](private-selection-hierarchy.md)。固定的core/scripts/cards.cdb/客户端及禁表均未更换。v2牌组显式设置`adapter_revision:5`，绑定`native-private-knowledge-v5`；旧v1/v2/v3/v4轨迹格式保留。工程示例位于`configs/private-knowledge-engineering-v5.json`，不是用户3＋8套牌表。

```bash

```

输出目录必须全新，不覆盖原始证据。命令限120秒，单用例另限30秒/2200响应，使用当前云端CPU。它运行4条机制路线、两种对方选择偏好及一条完整自然终局，共7条轨迹，每条再独立真实重放；没有新增模型训练、外部API或付费资源。过程退出不代表腾讯云计费停机。

## 私有确认与选择

固定服务端对`MSG_CONFIRM_CARDS(31)`按首卡区域分流：首卡在主卡组时，仅指定玩家收到确认。v5通过`DecisionRequest.private_reveals`向该观察者提供严格的`PrivateReveal(ref,observer,cards,message)`；每张仅有卡号、controller和deck区域。历史按身份规范整理，不保存牌序、原生下标或未选内容，不写入共同公开历史。

最多保留32次、每次128张确认；引用计数按各观察者独立，旧记录被淘汰时同时删去内部别名。历史表示过去见过的身份，不能当当前卡组库存。模型在观察者私有历史token中编码它，特征版本为`legal-player-dto-v5-private-knowledge-hierarchy`。旧特征权重拒绝静默载入，历史权重留在原版本。

内部可短暂保存确认时的真实位置关联。尚未洗切且候选的controller/区域/位置/身份全部匹配，选择才能携带`knowledge_ref`及已合法获知的身份；此确认不提供原所有者证据，owner保持null。DTO会拒绝跨观察者、缺少证据、超过所确认张数、虚构所有者或额外字段。

洗牌、抽卡、牌堆逆转、墓地/卡组互换，以及触及数组区的MOVE均清除相应关联；过去见过的卡名仍保留。不按原始卡号反查已确认多重集来恢复洗切后的匿名卡背。匿名候选仍使用独立私有置换键；键不进入DTO/模型/外部对手或公开工件。

真实上游脚本证据：

- 魔导书库 科瑞森`40230018`：己方隐藏卡组MSG26添加→移除→再添加，核心自动满足3张不同名；只向对手确认后真实洗牌，再由对手MSG15盲选。对手记得3个名字，但不获知卡背与名字的映射。
- 紧急救急救命救援`97926515`：英雄到来实际支付一半LP后发动；己方选择3张，再向对手确认，不先洗牌。对手能按确认身份选择其中1张，first/last两条返回都由核心接受并真实加入手牌。

不同隐藏世界在魔导书库的对手窗口得到相同请求摘要和全部模型张量。非法/旧action_id在原生提交前拒绝；坏原生MSG26/对方卡组响应仍由真实核心给出MSG_RETRY。混合区域的私有确认、更多隐藏区域机制、完整私有认知模型继续待验；不以这两个脚本宣称通用卡池通过。

## 盖放宿主与公共素材

固定客户端在公开超量宿主被盖放后保留先前的素材对象；服务端对进入OVERLAY的MOVE会向双方发送素材身份。v5仅从该广播和公开宿主查询建立公共素材缓存，原所有者缺少公共来源时为null。素材从EXTRA中的宿主搬到怪兽区时迁移关联；拔除/离场顺序调整子索引，未知盖放洗切或控制交换会丢弃关联。

对手盖放宿主只允许位置查询，不能查询其身份、攻守、owner或素材。若此前公共素材关联完整，可在隐藏宿主下展示这些素材及已知数量；宿主本身保持隐藏。丢失关联时不查询补齐，也不虚构素材数量。

真实救援猫→两张不同3星兽族→发条机雷 发条雷→月之书，展示两张已公开素材；再用黑洞破坏盖放宿主，双方素材观察清空并在墓地看到真实去向。测试另外用查询拦截器禁止对手隐藏宿主的身份/素材查询；主动丢弃缓存的投影负测是合成测试，不冒充真实MSG36卡效。
