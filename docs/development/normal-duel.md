## 对局与终止

补齐通常怪兽所需的回合、战斗阶段、攻击/对象、有限组合选择、公开移动、伤害、LP 和核心胜负消息。规则代理优先召唤、攻击，再按引擎允许的选项推进阶段；其他选择采用固定顺序。这是协议基线，不代表合理打牌或模型能力。

宿主负责初始牌序，`start_duel` 本身不洗牌。每位玩家的初始插入顺序由独立的 `random.Random(seed*2+player)` 洗切，牌效 RNG 则由真实核心 `create_duel_v2` 的种子序列控制。两者属于控制器内部，均不进入玩家请求。重放版本记录 Python 版本和这套初始牌序配方；不同种子的起手与轨迹差异已测试。

只有收到真实 `MSG_WIN` 才返回自然结果；终局后不再产生决策，迟到响应被拒绝，退出时释放核心。运行有决策数和墙钟预算，耗尽返回错误，不捏造胜负。此预算在 Python 调用边界检查，尚不能抢占卡死在原生调用中的线程；CLI 集成验证另有子进程超时。真实 PC 比赛独立计时/认输控制仍未实现。

## 观察与轨迹隔离

每次请求包含己方手牌、公开场面和计数，不查询对方手牌身份或任何牌组顺序。对方场卡先看表示，仅公开时取身份；墓地作为公开区域。真实合法盖放后，在另一玩家的实际观察中仍为 `hidden/card_id=null`，集成测试覆盖此点。公开 LP 随真实事件更新。

重放文件明确标记 `normal-duel-replay-not-policy-input`。它含独立复现种子、资源版本、双方选择/原生响应、玩家请求指纹、经过过滤的真实事件及终局。隐藏抽牌身份与移动的隐藏卡片 ID 不写入事件；不保存原生全信息载荷。该文件可由种子重建对局，**不得提供给策略或作为混合双方信息的训练观察**；策略只接收当时的 `DecisionRequest`，其种子为 null。

重放会重新创建真实核心、逐窗口比较观察/候选指纹、提交记录的实际响应，再比较全部过滤事件和终局；修改、截断或版本不符会失败。此格式是本项目 JSON 轨迹，**尚不是客户端 `.yrp` 回放或 PC 回放一致性证明**。

## 测量与边界

CLI 报告整局墙钟、CPU 时间、进程峰值 RSS、决策吞吐及循环时延中位数/P95/P99，保留每次时延原始采样；绑定硬件、OS、种子和轨迹版本。循环时延包含固定规则选择、响应、下一引擎提示与观察投影；总耗时还包含资源哈希/初始化，写文件和打印不纳入。RSS 是整个子进程峰值，在 Linux 为 KiB。

这是 Linux 云端、无模型/无搜索/无 GUI 的小卡池基线，不能外推神经网络吞吐、PC 端到端时延或训练样本能力；代理胜率不作为模型成绩。

当前仍拒绝非空效果连锁、未知消息和超出上限的组合选择。一般效果牌组、翻面/控制权等完整覆盖、标准回放、PC 客户端兼容、正式计时、三期数据/发行截止日、官方禁表对照及素材授权仍待完成。阶段 1A 整体验收没有通过。下一批再选少量真实效果与连锁用例，本批不扩展模型或改变既定架构。
