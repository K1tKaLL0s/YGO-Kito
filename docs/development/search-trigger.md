# M2d：真实卡组检索、确认公开、诱发及次数限制

固定核心和脚本不变。本批实际执行三眼怪 `26202165`、黑洞 `53129443`、死者苏生 `83764718`、愚蠢的埋葬 `81439173` 的上游 Lua。Python 不判断或改写诱发资格/次数；它选择核心候选，并核对真实事件。

```bash
.venv/bin/python -m ygo_kito native-search --route field-twice --trace outputs/search-field.json
.venv/bin/python -m ygo_kito native-search-replay outputs/search-field.json
.venv/bin/python -m ygo_kito native-search --route deck-grave --trace outputs/search-deck.json
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m unittest discover -s integration_tests -v
```

两条路线都是明确初始条件的测试，不计随机启动率：

- `field-twice`：玩家 0 为 36 张原通常怪兽＋三眼怪＋2 黑洞＋1 死者苏生；玩家 1 为原 40 张通常怪兽。种子 **9154** 使三眼怪、两张黑洞和苏生进入起手。先通常召唤三眼怪，黑洞送墓引发检索；再苏生，第二张黑洞同回合再送墓。核心只发动一次三眼怪效果。策略会选择任何再次提供的三眼怪发动，不是 Python 主动跳过第二次。
- `deck-grave`：玩家 0 为 38 张通常怪兽＋三眼怪＋愚蠢的埋葬；种子 **24** 使愚埋在手、三眼怪在卡组。从真实检索候选选择三眼怪送墓，没有满足“原来在场上”的诱发条件，核心不发动三眼怪效果。

实际牌表、种子、源码/资源版本、响应及事件写入 replay-not-policy-input 轨迹。社区禁表数量检查保留，不宣称官方对照或历史卡池冻结已经完成。场景在第一回合的检查点结束并释放本地核心，不宣称完整效果牌组或比赛投降成功。

## 通用选择接口及可见信息

新增可选的 `DecisionRequest.search_choices`：每个 `SearchChoice` 只有临时引用、合法展示的卡片 ID 和所属玩家。它不属于场面 `Observation.cards`，没有卡组区域坐标、牌序或原生响应索引。仅当核心当前提示允许选择者查看自己的检索候选时提供身份；**选择者可以合法看见未选中的合格候选**，这不同于把整副卡组或对方卡组泄露给策略。

原生候选顺序及位置被丢弃，对外按卡片 ID 排序，响应索引只保留在适配器内部。仅支持最多 128 项的单卡检索，线性生成动作；盲选代码 0、对方卡组、混合区域或更大/多卡组合明确拒绝。普通选择的原限制保留。没有候选时不猜测卡片身份，也不把未找到说成不可能。

下一决策窗口不再携带这批临时候选。对手投影不接收候选身份，公开历史不包含未选候选；非合格卡从未进入候选接口。策略投影的直接卡组内容/牌序查询被禁止，未来抽卡身份只在真实可见时进入当前玩家手牌。

搜索处理后的真实 `MSG_CONFIRM_CARDS` 把选中卡公开给另一玩家；公开历史记录该身份，双方一致。核心会洗切手牌时，适配器清除已知槽位映射，保留“曾公开加入这张卡”的事实，不伪造其当前手牌位置。公开确认导致的 `PROCESSOR_WAIT` 按固定核心源码恢复，这是 UI 暂停，不发送虚构合法响应；其他无支持提示的等待仍失败。

`search_choices` 为空时序列化省略该字段，因此已有通常怪兽/费用连锁的请求指纹和冻结轨迹保持可重放。新增候选只在拥有合法检索窗口的玩家请求内出现。审计轨迹记录选择者当时合法看见的候选及复现种子，属于控制器私有记录，不是对手公开历史或训练策略输入。

## 验证及下一缺口

37 项单元测试＋19 项真实核心集成测试通过，保留 M2b/M2c 完整回归及冻结轨迹重放。新增实际检索、公开确认、同回合同卡复活后次数限制、从卡组送墓不诱发、候选隔离和不查询牌序的检查；单元检查还改变原生顺序/位置，确认对外候选不变且内部响应映射正确。

本批没有单独验证另一同名副本共享次数、跨回合次数重置、三眼怪检索卡的同名效果发动封锁；所选加入手牌卡为通常怪兽，不能冒充这些限制的通过证据。也没有支持多卡检索、额外/除外/叠放选择、通用诱发排序、标准 `.yrp` 或 PC 客户端门槛。下一最小缺口可先验证一次跨回合次数重置，再扩展其他选择类型；阶段 1A 整体仍未通过。
