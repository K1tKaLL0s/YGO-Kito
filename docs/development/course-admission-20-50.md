# 构筑、CB 与预测反馈的暂停边界

本次用户指令覆盖此前允许 unknown CB 进入对战的规则。正式对战必须同时满足当前构筑自己的任务证明、成功的条件 CB，以及适用的构筑评分条件。旧课程记录不按新规则重写。

## 原预测反馈只下调数量

用户原意是：实际胜率在百场内明显低于预测时提示重新评估构筑，在千场内明显低于预测时强制重新构筑。现在数量变为 20/50，触发仍必须有低于预测的证据，不能把局数本身当优化理由。

`FeedbackPolicy.twenty_fifty()` 声明新的独立 epoch。每 5 场检查一次、最少 5 场、差额 0.1、alpha 0.05、Hoeffding 界和 forecast alpha spending 均为工程口径，尚未经验校准，不能称为用户指定数值。20 场内的已确认低表现发复评信号，20–50 场内继续低表现发强制重构信号。

比较使用预先登记的冻结策略、任务、构筑、对手分布、版本和先后手范围。仅收到真实终局、无系统/操作/未知诊断的完整比赛计入该窗口。预算截断保留审计，不计比赛、胜负或奖励。旧 100/1000 controller 和 SQLite 留在原路径，新 epoch 单独保存。

实际训练样本闭合后，课程必须完成对应冻结观察才可继续下一训练样本，避免调度器一直选择 train_duel。一次失败或一次换卡都不能代替显著性比较。

## 构筑自己的条件 CB

CB 基于当前构筑卡效和明确指定的假设起手推理，不要求随机抽中起手。准入检查复用已保存的条件初态、实际动作、素材、事件、目标和资源版本证据；不会为了检查准入再次运行原生引擎。

`routes_inferred` 标签本身不足以准入。unknown、not_run、别的构筑的路线、随机起手未命中都不能作为成功。只由真实完成的条件推理 producer 发出事件；连续两次无已验证路线发优化请求，重复 guard 不增加次数。成功清除连续失败。优化完成只确认其开始前的触发事件，不吞掉本轮新失败。

## 评分及提示的适用范围

2207/2210 的明确珠泪目标使用对应参考 70 分锚，低于 56 分强制优化。候选必须重新检查自身卡文、条件、成本、资源、限制与功能关系，不能继承参考构筑的情境系数。评分是专家先验，不能当胜率、原生 CB 证明或已训练能力。

2610 自选主题、自主构筑，不套旧参考的 70/56 或主轴/副轴/泛用提示。其他主题必须显式提供自己的目标先验，不能默认按墓地/融合加分。

只有独立完成的候选评估推进低分/提示计数；重复 evaluation、candidate/cycle 或准入查询不推进。低分第 2/4/6 次按独立评分契约释放主轴/副轴/泛用匿名效果积木。语义不足保留 unknown，不制造数字低分或提示次数。learner 只接收公开标量与已释放提示，参考卡表、语义源清单、私有审计和计数状态留在 evaluator 私有目录。

## 计算截断与恢复

`SampleBudgetExceeded` 保存私有未完成动作轨迹、资源边界和 RNG 证据；它不是可继续的原生半局 checkpoint。不得生成终局奖励、胜负或 PPO 更新。只有已声明的下一采样尝试可前进，训练更新游标独立记录；优化器更新前报错不能发布临时采样游标。

恢复检查实际 duel update 边界、去重的已确认旧截断和新截断回执，并核验私有 partial 文件。train-46 的旧错误只能通过显式、精确的无更新确认迁移；不改旧记录，不伪造遗失的动作轨迹。真正不确定的原生/优化器故障继续停在 inspection。

新源码应先形成独立暂停代并显式绑定迁移。旧源码、checkpoint16、原暂停代和历史账本保持不动；没有准入成功证据不得解除正式训练 hold。

用户随后明确要求修复后继续暂停，待其审查整个项目并明确批准才恢复。此前“修好后继续训练”的许可不再构成恢复授权；即使技术准入通过，也必须保留这一人工暂停边界。
