# 构筑候选与静态评价优化

2026-11-11，实施分支 `codex/construction`，对照基线 `ba65e84`。

## 运行变化

每轮从换卡、轴组合和配套修复中先挑方案。现有构筑 Transformer 批量排序，规则检查张数、同名卡合计、禁限和原任务硬条件。骨架补全及每轮换卡都最多组出 5 份完整牌表。完成静态排序和指定参考比较后，只保存最优构筑。满足条件且已授权时，仅这份构筑进入基础 CB。待评批次的牌表只随权威存档保存，独立导出只列标识和状态。现有对战训练可继续比较已部署构筑与新赢家。

参考复用同一份已绑定评价。输入变化时重算，比较每份候选时继续使用共享未知条件与原参考比例。固定资源不足由匹配提前证明，复杂流转仍保留各自的资源见证。相同条件结果复用评分，换卡时优先沿关系图更新受影响部分。

正式构筑 CLI 和配置式宿主入口默认 `cuda:0`。已验证的认知图网络预测可在宿主启用辅助模式后影响下一轮换卡方向。模型和图查询在所绑定设备上批量运行，规则核对和动态资源搜索由宿主计算。

## 同输入对照

同一套合成牌表重复五次。完整组表次数使用候选预算原为 12 的 40/15 张夹具，静态数据使用同样的四份完整牌表。耗时取中位数，内存取同一口径的进程峰值。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 一轮实际新组完整牌表 | 404 | 4 |
| 进入本轮评价的候选含原构筑 | 12 | 5 |
| 一轮组表 | 151 ms | 104 ms |
| 首份完整静态评价 | 313 ms | 293 ms |
| 静态整轮 | 1.209 s | 0.685 s |
| 进程峰值内存 | 359 MB | 350 MB |
| 完成后进度数据 | 754 KB | 135 KB |
| 结果数据 | 2.60 MB | 573 KB |
| 1 秒内最高有效分 S | 5.351998837112446 | 5.351998837112446 |

四份牌表的分值、区间、最优构筑和准入结果一致。另以 25 组主题、Side、未知条件和强制影响夹具对照，完整评价标识一致。10 项相关未知的 1,024 种组合保留原评价结果，实测由 4.04 秒降至 0.15–0.31 秒。相邻换卡的匹配图与条件复用测试中，资源分配步骤由 22 次降至 11 次，改动涉及的关系和整份评分与冷启动结果一致。

CUDA 对照使用项目 WSL Python 3.12.14、PyTorch 2.9.1+cu128、RTX 4060 Laptop GPU。相同牌表从旧牌表入口和新投入数量入口得到逐项相同的五个输入张量和 Transformer 分数。实际换卡入口先在 `cuda:0` 批量评价方案，再组出 4 份完整新牌表，连同原构筑共 5 份。
