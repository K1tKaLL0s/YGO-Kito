# 构筑模块全面核对与旧入口清理执行书

> 执行与历史记录。现行行为以 [现行设计](../../current/README.md) 为准；本文的日期状态和当时授权不自动适用于新任务。

用户目标：全面对照原设计检查构筑模块的软件实现、代码质量和正式训练调用链，直接清理明确不再调用的入口、代码及规则，避免训练误用旧路径。沿用当前主进程执行，不启动子代理，仅必要静态检查，不启动训练、CB、真实模型推理或依赖安装。

## 当前证据与完成标准

依据为原正式优化方案第 2、9、10、11 节、用户后续主次百分比修订及实际源码；此前 68 项静态结果复用为回归基础，不以旧验收表代替本次源码核对。已定位：

1. `construction_contract.py` 的 `construction_quality_v4`／70、56 草稿只有自身测试引用，没有产品或训练调用。
2. `construction_quality.py` 中 `GenericFit`、`DuplicatePurpose`、`SideValue`、`SlotUse`、`QualityLoss`、`SideDeck` 及旧七项常量仅旧评分测试消费；旧档迁移直接保存原字典，不依赖这些类型。
3. 当前政策验证已经要求 v4 配置和显式 pass 模式，但 `construction_fill.py` 仍保留不可进入的旧排序、选中后补算质量、schema 2 新建及旧百分制摘要分支；`construction_progress.py` 亦有前置拒绝后不可能执行的旧绑定返回。
4. `ConstructionLayerAdapter.evaluate` 已拒绝旧政策，但其单候选层投影仍带着旧多候选偏序排序实现；该排序结果被丢弃。`order_by_layers` 仍被当前质量样本的偏好环检查调用，保留其通用作用。
5. `design_supervisor.py::inspect_artifact` 仍硬编码接受旧准入 v2，且没有按当前骨架／优化职责区分具体输出；这是实际监督调用点，修复而非删除。
6. 原设计第 10.1 节的两次确认不足与主轴→副轴→泛用提示尚无运行接线；当前仅有库存停滞计数。

完成标准：活动构筑和训练调用链只有当前功能分政策、逐候选评价、最终 S 比较及准入；旧档只读取并转成待重评，不重新执行旧算法。明确未调用的旧模块和旧规则删除；必要诊断、骨架依据、当前成对训练接口及迁移数据保留。连续不足计数按真实已完成尝试归属，恢复不重复计数，unknown／错误／预算／暂停不计失败，提示不暴露参考卡名、配方或精确投入。每个删除项有引用检索依据，每个实际修复有定向静态证据；更新当前文档和验收对齐。

## 允许与禁止范围

允许修改：构筑评分、层适配、填卡、候选选择、恢复与反馈；监督脚本和真实训练调用点中与当前构筑接口衔接的代码；对应静态测试、维护文档及 CPU 白名单中的过期测试登记。明确删除候选为 `src/ygo_kito/construction_contract.py`、其专属 `tests/test_construction_contract.py`、纯旧百分制 `tests/test_construction_quality.py`、上述旧类型及旧分支。其余删除须先确认全仓调用、脚本参数、动态导入和现行测试引用，再补入本执行书，不按“名字旧”批量删除。

禁止修改或运行：模型结构、权重、优化器和真实训练行为、课程存档／暂停／指针、原生或 ABI、并行识别内部实现及其整组验证、外部配置、Pro 辅助核验程序。训练脚本仅阅读和修正调用字段，不启动。保留工作区既有未提交修改、删除与未跟踪文件，不 reset／clean、不提交推送、不另建替代工作树。
