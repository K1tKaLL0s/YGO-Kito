## 2. 五组评价项应怎样计算和解释

先固定同一任务、环境、目标及本轮比较的用途要求。要求来自原任务和已确认的功能逻辑，不来自候选恰好拥有哪些标签；不同实现方式允许作为“或”选择。原目标需要的能力不能通过删掉模块或改小分母来消失。

| 评价项 | 具体输入和判断 | 需要避免的错误 |
|---|---|---|
| 功能供给与有效投入 | 沿用每项功能的实际张数K、有效投入E、占位和密度；区分主动取得、已有资源条件及对方动作响应；目标依赖的准备、转换和产出均应被覆盖 | 标签多不等于牌强；小骨架的高密度不等于供给足够；不要求所有牌组都有同一套功能 |
| 条件和资源接续 | 按“用途”核对费用、对象、素材、区域、事件来源和取得前提，复用supported/missing/unknown；必要输入共同满足，替代输入按或处理；保留共同瓶颈与已知循环入口缺口 | 牌在卡组中不等于能够取得；两条边分别成立不等于资源能同时分配；效果数量或原始边数不能直接合分 |
| 次数与限制相容 | 对当前声明同时需要的用途检查同名次数、共享资源、通召机会、自肃与已知顺序依赖；互为替代的用途可以增加选择余地，但其收益不相加成同时产出 | 不能把共享一次的两个效果都算满；不能仅因两张卡存在限制就整包扣分；能靠已有顺序条件共存时保留该条件 |
| 重复投入与卡位效率 | 比较增减一张后，取得机会、留库、备用、续航或替代用途究竟改变什么，同时计算失去的原用途及占位 | 第二、第三张并非天然废件；不同卡名也可能同质冗余；同名0.9/0.8折扣不得再叠加一份重复惩罚 |
| 泛用和环境适配 | 用同一语义检查该卡在当前环境解决什么问题、触发和支付条件是否适合己方、与本轴有何冲突，以及占位替换损失；按已声明的对手或问题范围比较 | 不按“泛用卡”名录自动给分；不奖励名气或照抄参考；没有对手分布依据时不伪造环境胜率 |

主卡同名有效份数沿用用户已确认规则：第一张1，其后每张0.9，即1／1.9／2.8；额外沿用1／1.8／2.6。E是配置统计量，不是物理张数，也不是可发动次数。

若已有明确的可取得卡集合，需要比较一张与多张的起手收益，可以沿用第二层允许的简单取得概率：从N张中抽h张，K张满足已声明条件，至少出现一张的概率为 `1 - C(N-K,h)/C(N,h)`。这里使用真实K，不使用E。只有该集合及条件已经明确时才算；不能把所有带“检索”标签的卡都算成独立入口，更不能把此局部概率称为完整CB成功率。无须为这一步启动起手模拟或动作搜索。

随机资源准备在构筑评价中仍有价值：分别看来源投入、接收用途和已有条件下的局部取得机会。基础CB不展开随机命中分支，不意味着构筑评分把随机相关卡的价值归零；也不能用“E×每次堆墓数量”宣称一回合产量。

## 3. Main／Extra／Side分别解释什么

Main主要回答：需要的资源能否取得，准备、转换、交互及恢复的投入是否适合当前目标，条件件是否有支撑，泛用占位是否值得。

Extra主要回答：目标及工具用途是否覆盖，Main能否提供相应素材和条件，已知限制是否相容，重复投入是否有明确备用或续航价值。额外放有一张目标，不能独自计为已获得其收益；依赖Main的接入说明必须保留。相同联合收益在总分中只计一次，可以在两区解释其来源，不能把主卡素材、额外目标及连接关系各奖励一遍。

Side主要回答：对哪些已声明的问题有改善，换入什么、换出什么，换后原目标和必要配套是否仍在，是否有足够可取得的投入。可以比较少量明确换备方案，不必穷举所有换备组合。Side不补当前Main／Extra的缺口。任务确实不要求Side时记不适用；任务要求Side时，不能由候选自己删去该评价来提高分数。

没有Extra的策略、响应型策略或纯轴策略均按自身目标评价，不因缺少融合、混轴等非必需结构而扣分。不同策略比较共同的目标能力与资源代价，而非同一张卡表或怪兽／魔陷比例。

## 4. 怎样形成分数，避免把统计项机械相加

先处理合法性、原目标和必要配套，再比较质量。已知必要功能缺失不能由其他优点抵消。质量按用途归并，K、E、密度、关系状态等是解释同一用途的证据，不是可以各加一遍分的独立收益。

一个可供实施的简单合分形式是：每区得到0—100的质量分，再按固定评价口径合成 `S = wM·SM + wE·SE + wS·SS`，权重和为1。每区内部同样只对已定义、可解释且去重的评价项合分。每项必须保存原始量、适用条件、归一化依据和不足原因。尚无依据的量不能随意填0.5；未知影响相关用途，不自动否定整副牌的其他已知改进。

这只是建议的最简形式，不是现有代码已实现的公式。权重可以存在，但应属于共同任务目标和评价模式，不属于卡名、主题或当前候选。初版可以从适用的一级维度等权开始观察，或复用任务已有明确优先级；都应在对比参考之前固定，之后有机制依据才修改。不在本文件冻结60%／25%／15%或其他新比例。

不适用项由任务确定并在整组对比中一致处理。不能让候选删除Extra、Side或难满足的用途后自行重分配权重。跨区联合收益明确归属一次；分区数用于解释贡献，不能遮盖联合条件。

给分前应先能回答三个问题：这个数字表示什么能力；增加一张卡为什么使它变好或变坏；换个卡名但保留相同语义时是否得到相同判断。回答不了时，应先补齐指标含义，不靠参考归一公式掩盖。

## 5. 参考构筑、70分和通关线怎样使用

参考构筑是质量锚点和对照样本，不是生成器答案或每个组件的最低配额。参考与候选必须经过同一个评价器、同一环境和同一目标口径；评价器不能因“这是参考”给予额外加分。

先看排序及原因，再看总分尺度。例如旧2207对照中，入口有效投入同为9.4，参考主轴占18位、候选占21位；参考用更少位置保留了同量入口候选，同时送墓融合组件有效量为6.6对3.8。它说明占位与某项资源转换投入的差异，不等于参考起手成功率已经更高，更不等于未选某个副轴应被扣分。完整评价还应计入候选多占位置所带来的实际用途。

最有用的校准变化是：保持原目标，补齐一个确切缺口；增加一个真实替代而保留其他用途；把一张无边际用途的重复位换成能解决既定问题的卡。若实际收益和损失明确，评分方向应符合解释；如果存在取舍，就报告取舍而非规定所有改动都必须涨分。不要制作“必定让参考获胜”的测试。

70属于用户对完整质量的人工尺度，算法不必机械输出70。结果若明显背离，应查明漏掉了哪些收益、把哪些条件收益算满、哪里重复计分或标尺不合适；不能直接乘系数把参考拉到70。60／40只用于原范围下的质量判断，不作为新轴骨架层的断言。

历史56来自参考70的80%。若继续沿用此前80%参考水准的通关思路，我建议将它落实为同一完整尺度上的 `T = 0.8 × S(reference)`，同时满足原有硬要求。例如完整评价对参考得到75，则该比例对应60，而不是永远写死56。这是待实施建议，尚未写入生产；比例依赖共同尺度，不能直接乘K、E或局部分项。70本身也不应自动变成所有候选的通关线。

按参考比例设线时，参考及评价版本应在一轮比较／课程中固定，不能随候选改分母。其他环境使用各自合法且适配的参考；没有对应参考时应标明该比例政策不适用，不能拿2207牌表给所有策略规定模板。先完成已有参考环境的接入，不把建立全球统一排名变成当前前置任务。
